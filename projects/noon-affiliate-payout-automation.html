In Short

The problem

Each month, payouts had to be calculated, requested from finance, approved and paid to each affiliate, then explained to them. Every hand-off was manual, so payments took around three months.

What I built

SQL that calculates every payout, automated emails that send finance the full payout request and each affiliate their own report, and sales forecasts that tell finance the bill before the month closes.

The result

Affiliates paid three times faster, $150K saved every year, and a budget estimate finance could trust, landing within 10% of the final figure.

How It Works

Key Decisions

All payout logic in one place

Every commission rule lives in SQL, so finance, the affiliate team and affiliates always see the same number, and any figure can be traced.

Trade-off: rule changes need a code change, not a spreadsheet edit.

Automate every hand-off

Anything that used to be copied, pasted or emailed by hand became an automated step, from the finance request to each affiliate's statement.

Trade-off: late source data has to be caught before the emails go out.

Give finance the number early

A sales forecast estimates the payout before the month closes, so the budget is reserved before it is needed.

Trade-off: an estimate, not the final figure, within about 10%.

One owner, end to end

I owned the process from data to payout, so there were no gaps between teams where a payment could stall.

Trade-off: relies on clear documentation for hand-over.
